# Audit 2026-09-08 — image findings carried back from openmixer

Branch `audit/openmixer-image-findings`, from `main` at 5ea3a8b (clean tree). Read-only against
the machine: no build, no VM, no podman was run; every claim below is a file:line reading, and a
change made here is unbuilt until the atomic workflow runs it.

Sources: the openmixer console image was copied from this repo's `atomic/` tree on 2026-09-08
(`docs/design/specs/2026-09-08-installable-atomic-desktop.md` §1 there names what was copied,
what was refused and why). Building it turned up a handful of things that are also true of the
original. This document brings them back. Three were small enough to fix on this branch; the rest
are proposals with the evidence, for the maintainer to accept or refuse.

| 1 | Chromium trusts a self-issued CA through the system store, never `--ignore-certificate-errors --test-type` | **applies** — and the opt-out is dead | `xiboplayer-chromium/xiboplayer/launch-kiosk.sh:513-515`: `${RELAX_SSL_CERTS:-true}` adds both flags. The kiosk wizard writes `~/.config/xiboplayer/chromium/config.json` with only `cmsUrl`/`cmsKey`/`displayName` (`kiosk/xibo-zenity-lib.sh:271-282`), the launcher reads that same file (`launch-kiosk.sh:16-17`), so on every wizard-built kiosk the key is absent and TLS validation is off for every origin the player loads, not only media. Worse: `cfg_read` is `jq -r ".$key // empty"` (`launch-kiosk.sh:48-53`) and jq's `//` treats `false` as absent — probed: `{"relaxSslCerts":false}` yields an empty string, identical to `{}` — so the documented opt-out (`launch-kiosk.sh:512`, `xiboplayer-www/content/en/docs/configuration.md:31`) cannot switch the flag off, and the RPM's shipped default `xiboplayer/config.json:17` (`false`) is read as `true`. Every boolean read through `cfg_read` has the same hole (`kioskMode`, `fullscreen`, `hideMouseCursor`, `preventSleep`). Docs disagree with each other on the default (`www …/players/chromium.md:102` says `true`, `…/docs/configuration.md:31` says `false`). Electron scopes it correctly (`xiboplayer-electron/src/main.js:596-633`: media permissive, CMS strict); a Chromium flag cannot be scoped. The mechanism openmixer relies on is available here: the image installs the Fedora RPM `chromium` (`xiboplayer-chromium.spec` `Requires: (chromium or google-chrome-stable)`), whose NSS roots module is p11-kit, so `/etc/pki/ca-trust/source/anchors/<ca>.crt` + `update-ca-trust extract` (or `trust anchor <file>`) is honoured with no `certutil`/`~/.pki/nssdb` step. | In `xiboplayer-chromium`: fix `cfg_read` for booleans (`if has("k") then .k else empty end`, or `jq -r '.k | select(. != null)'`), make the default `false` in one place and say so in one place. In this repo: a doas-permitted `kiosk/xibo-trust-ca.sh <file-or-url>` that anchors a CMS CA (`trust anchor`, idempotent, `--remove`), reachable from the picker's CMS step and from `xibo-usb-preseed.sh` (a `ca.crt` beside the preseed is the natural carrier for a fleet).
